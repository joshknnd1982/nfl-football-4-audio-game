## B. Bugs and lessons, continued (part 17 is full; sections C and D are in part 16)

- **B-P236 (2026-11-19) A right the game tells the player (a practice squad elevation) needs a menu that does it, also where the staff already filled the place.** Symptom: in nfl4 a tester's only punter was out for three games; the staff had signed a made-up stand-in, injured reserve was refused (too few punters), and after he added a punter to his practice squad he found no way to play him ("If a player is hurt you should be able to elevate a player. This is not possible."), although the practice squad rules item said a squad player "may be brought up for a game". Cause: the elevation existed only as the staff's automatic rule, made when the week's stand-in was first needed, and the stand-in was kept to the season's end, so a squad man added later never played; the "who starts in his place?" choice offered the roster's men only, and nothing at all when the staff's choice was a stand-in. Fix: the player's own elevation, from both places he looks: the who-starts choice lists the squad men of the place's family after the roster's men (and after the staff's stand-in when nobody of the team can play), and the practice squad menu gets an "elevate" item that starts from the squad man; the league's limits checked at the choice (two a game counting the staff's own, three a player a regular season, one place a man), counted when the game is played, and the choice dropped after the game (he goes back to the squad) and again at the week's settle. The elevated man plays with a stand-in's identity, so he is never hurt and gets no carries, at his own rating but never above the hurt man's. Keep the staff's automatic rule as it was, so no computer team's lineup or draw changes. Check: tests of the tester's case (the stand-in first, the squad man second; he plays the place; the count after the game; the limits; the menu item says why not), and a scan of every rules text for a promise no menu keeps (rule 0.28 (4)). Lesson: when a rules text says the player "may" do something, find the menu that does it before shipping the text; when a staff fills a gap automatically, the player's own choice must still be able to replace what the staff chose. Found: nfl4, 2026-11-19 (D-247, GitHub issue 19). Related A125, B-P210, B-S38.
- **B-W52 (2026-11-19) A code that no key sends reached the menus as a key, so a menu said its item thirteen times.** Symptom: in nfl4 a tester held Alt with JAWS running; the log shows 13 key-down messages of vk 252 in 0.4 seconds, each read by the menu as an unknown key, so the menu said "add to the practice squad" 13 times. Cause: the key queue dropped only the keys Windows keeps (volume, media) and turned the laptop stand-ins; every other code went to the game. Programs (a screen reader, a hotkey tool) send codes that no key has so that a lone Alt or Windows key opens no menu: Microsoft's "Virtual-Key Codes" page lists them as Reserved (0x07, 0x0A-0B, 0x5E, 0x88-8F, 0xC1-C2, 0xE0, 0xFC VK_NONAME), Unassigned (0x0E-0F, 0x97-9F, 0xE8) or Undefined (0x3A-40), and 0xFF is on no list. Fix: drop those codes where keys enter the program (the key queue's post), with one log line each (why="not a key"), in every mode, before any other mapping; the window still logs the key-down, so a report shows them. Check: a test posts them and finds no key waiting, posts Enter and finds it, and requires that no real key's code is in the set. Lesson: a menu that answers an unknown key by saying its item again turns any burst of injected codes into repeated speech; filter by the official list of codes, not by the one code a log showed. Found: nfl4, 2026-11-19 (D-248, GitHub issue 19). Related B-W43, B-W44, B-S37.
- **B-T160 (2026-11-19) A text written into a generated file by hand is lost at the next generation, and it skipped the generator's checks.** Symptom: in nfl4 the next session's text generation dropped three menu texts of the newest build (its depth chart item and its two sentences) and reverted a help line, and five tests failed with KeyError; the hand-written help line was also 235 characters, over the 200 the generator allows. Cause: the session that added them edited the generated module (nx_texts.py) and the generated list (STRINGS_NX) directly, never the master table (strings_nx.tsv), so nothing failed until the module was made again from the table. Fix: the rows put into the master table (the help line shortened to fit), the module generated again; a test now requires the generated module to hold exactly the table's rows (every ID, text, speaker and kind, nothing more) and every text within the limit. Check: that test, and after any text change run the table's checker and the generator, never an editor on the generated file (its header says so). Lesson: before regenerating, compare the old generated file with the new one and look for lost or changed entries; a file marked GENERATED is never edited by hand, even for one line. Found: nfl4, 2026-11-19 (S-D for issue 19). Related B-T146.
