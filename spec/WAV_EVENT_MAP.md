## 1. How the program names, loads and plays a wav

- File name: `<program folder>` + `\` + `foot` + number + `.wav` (App.Path). All 26 files are loaded from disk at the moment of use (no cache); only crowd 1, crowd 2, the hike and the play noise (foot1, foot2, foot3, foot14) are loaded once at start-up and kept. [CODE]
- Set-up (Form_Load): `Set dx = New DirectX8`, `Set ds = dx.DirectSoundCreate("")` (default device), `ds.SetCooperativeLevel(hWnd, DSSCL_PRIORITY = 2)`, one shared buffer description with flags 224 = DSBCAPS_CTRLFREQUENCY (0x20) + DSBCAPS_CTRLPAN (0x40) + DSBCAPS_CTRLVOLUME (0x80); every buffer is made with `ds.CreateSoundBufferFromFile(file, description)`. [CODE; names INFERRED from use, section 3]
- Buffers (private form fields): Me.m220 the one-shot buffer (intro, play, play2, playcel, ChangeVoice), Me.m224 crowd 1, Me.m228 crowd 2, Me.m22c hike (foot3), Me.m230 ambient (PlayRan), Me.m234 tackle (PlayTackle), Me.m238 play noise (foot14). Reloading a one-shot replaces the buffer; `play` and `play2` set the buffer to Nothing after use. [CODE]
- Every buffer: SetCurrentPosition(0), SetVolume(base + wavol), and for all but play2 and ChangeVoice's intro: SetFrequency(GetFrequency + 1) (a rise of 1 Hz, inaudible; the clone plays at the file's own rate; S5.2 correction: crowd 1 and crowd 2 set no frequency at all and keep the file's rate, ChangeVoice's foot0 does get + 1 (GoSub 0x428939, 0x428cc6), and the celebration sounds get + 100 x k as in their rows). play2 sets the frequency to 0 (DSBFREQUENCY_ORIGINAL, from an unused local Variant that is Empty). [CODE]

## 3. The DirectX 8 for Visual Basic methods behind the vtable offsets (Q-024 answered)

The type library dx8vb.dll is not on this PC (Q-005) and no web source lists the method order of its DirectSound interfaces (searches 2026-10-13: Microsoft DirectSound pages, vb-fun.de tip 0431, ActiveVB DirectSound tutorial). The names below are the dx8vb names for the same operations as in the native IDirectSoundBuffer8 (confirmed as VB-level names by the two VB6 examples). The offsets are tied to the names by their use in every call site (arguments, results, order of use), and the order agrees with the native header order (GetVolume, GetPan, GetFrequency, GetStatus ... Play, SetCurrentPosition, SetVolume, SetPan, SetFrequency, Stop). Tag: INFERRED, strong (every offset is used with one meaning only, no call contradicts a name).

| object | offset | method | arguments and results seen | evidence in the code |
|---|---|---|---|---|
| DirectX8 | 0x0c | DirectSoundCreate(deviceGuid As String) As DirectSound8 | "" = default device | Form_Load, result used as ds |
| DirectSound8 | 0x18 | CreateSoundBufferFromFile(file As String, desc As DSBUFFERDESC) As DirectSoundSecondaryBuffer8 | App.Path + "\foot" + n + ".wav", the shared description | 32 call sites, result stored in a buffer field |
| DirectSound8 | 0x28 | SetCooperativeLevel(hWnd, level) | Form1.hWnd, 2 (DSSCL_PRIORITY) | Form_Load only |
| buffer | 0x24 | GetVolume() As Long | hundredths of a dB, 0 to -10000 | read, then 0x48 writes base + wavol (c2uh, c2uf, c2dh, c2df, adjvol) |
| buffer | 0x2c | GetFrequency() As Long | Hz | read, +1 or + a random offset, then 0x50 writes it |
| buffer | 0x30 | GetStatus() As Long | 1 = DSBSTATUS_PLAYING | wait loops "until status <> 1" (play, playcel, Form_Load) |

## 4. Sound procedures: exact behavior

- Sound volume `wavol` (form variable): starts 0 (football.vol), adjusted in the second half of F11: Up adds 100 up to 0 ("volume maximum" when it reaches 0), Down subtracts 100 down to -5000 ("volume minimum"; the words " volume higher ", " volume lower " otherwise). It is added to the base volume of every sound. DirectSound volume v is an attenuation in hundredths of a decibel: amplitude = 10 ^ (v / 2000). [CODE]
- play(n, v): clk (clears the key), load foot<n>, position 0, volume v + wavol, frequency + 1, play once, wait with DoEvents while status = 1, stop, release. Waits to the end, a key does not stop it. [CODE]
- play2(stem): clk, load <stem>.wav, volume wavol, frequency original, play once, wait while the sound plays and g = "" (a key press stops it, and the key is lost: the caller clears it, adjvol calls clk), stop, release. [CODE]
- PlayTackle(n): foot(n + 3) into the tackle buffer at -1500 + wavol, plays once without waiting, stops the play noise buffer, then waits 2.5 s (dy 2.5; keys are processed but do not shorten it). [CODE]
- MakeHike, PlayHike, MakePlayNoise, PlayNoise: see the files table; PlayHike plays foot3 once, then starts the play noise (loop at -2750 + wavol). The play noise runs until PlayTackle stops it. [CODE]
- Crowd 2 ramps (steps of 100 every 0.1 s, `dy(0.1)`): c2uf from the current volume up to wavol; c2dh from the current volume down to -600 + wavol; c2df down to -1200 + wavol. The loops do nothing when the current volume is already past the end (VB For with a step in the wrong direction). c2uh is meant as "up to half" but its end value is the current volume + wavol - 600, which is always below the start for wavol <= 0, so it never changes the volume (it only reads the volume twice): the original has no up-to-half ramp; the clone does the same (no ramp). [CODE, quirk, D-023]
- PlayRan (ambient sounds while a key is awaited): called on every pass of the getkey2 wait loop. Returns at once while the ambient buffer is still playing or Timer < st4. Otherwise: Randomize Timer; n = Int(Rnd * 3) + 1 picks foot8 (-250), foot9 (-1200) or foot10 (pan, volume as in the files table); loads it, volume + wavol, frequency + 1, pan, plays once (not waited), then st4 = Timer + Rnd * 7 + 3 (3 to 10 seconds). getkey2 sets st4 = Timer + 5 when it starts, so the first ambient sound comes after 5 seconds of waiting. getkey (the other wait) never plays ambient sounds. [CODE]
- playcel (touchdown celebration): Randomize Timer; c2uf (crowd 2 up to full); then 8 to 15 sounds (Int(Rnd * 8) + 8), each a random foot15 to foot24 at -300 + wavol with a random pitch: frequency = original + 100 * k, k = Int(Rnd * 40) - 20 drawn again while it is 0, and not below 8000 Hz; each one is waited to its end before the next; then dy(0.4), play("12", -500) and c2df. [CODE]
- adjvol, second half (sound volume): crowd 1 is set to -100 + wavol and crowd 2 is ramped up to full (c2uf) so the player hears the effect; every Up or Down changes wavol, sets crowd 1 and crowd 2 to (volume read at entry) + wavol, and plays foot0 with play2 (a key pressed during that demo sound only stops it and is lost); Enter sets crowd 1 = crwd1 + wavol, crowd 2 = (volume read before the ramp) + wavol, the hike buffer to -1600 + wavol and saves football.vol. Because the volumes read at entry already contain the entry value of wavol, the changed volumes add it twice when wavol was not 0 at entry (a latent bug of the original: the crowd gets quieter by the entry value; the clone computes the crowd levels from the base values and wavol alone, D-023). [CODE (lifted), quirk]
