## 0. Core rules

0.1 Scope. Only: Jim Kitchen's Windows audio games, menus, utilities (Visual Basic 6); PCS Games titles (MS-DOS, text-based, wav sounds; e.g. cops98, Any Night Football, PCS Games World Series Baseball); older MS-DOS programs of that kind incl. precompiled QuickBASIC EXEs; other very old, abandoned, simple text-based audio games and utilities for blind screen-reader users. For those last ones, check by web search that the title is no longer sold or supported and record the evidence; ask the owner only if the evidence is unclear. Anything else (modern commercial, graphics-dependent, still sold or supported): stop, say why, ask.
0.2 One game at a time, one folder each (section 4); refuse two games in one session. A menu program that launches games is its own project; launched games are separate projects listed as "child games" in its spec.
0.3 Evidence over memory: tag every finding (5.3); never fill gaps from similar games; unknowns go to `OPEN_QUESTIONS.md`.
0.4 Originals read-only: work on copies, record SHA-256 of each, never modify, rename, or delete `original/`.
0.5 Attribution: every game says "This is inspired by Jim Kitchen" (PCS titles: "inspired by the original PCS Games title and its creator") in README, About item, startup speech once per launch, and source headers. Jim Kitchen games add a respectful note: blind from birth, made these games free for the blind community, died in 2015.
0.5.1 Title format (owner rule, 2026-10-13, every game): the window title and the spoken startup title read "<Game name> by Josh Kennedy, inspired by <original author>", for example "My Brain by Josh Kennedy, inspired by Jim Kitchen" (PCS titles and others: the original author or company if known, else "the original PCS Games title and its creator"). This replaces the original caption and its spoken title, and it carries the 0.5 attribution, so the startup speech has no separate "This is inspired by" sentence (About, help and README keep the longer text). Record the original strings in STRINGS.md next to the new ones and keep the conformance test on the new ones. Amended 2026-10-18 by 0.16: the SPOKEN startup title is now the welcome sentence of 0.16; the window title stays as written here.
0.6 Never claim work not done or run; if a tool is missing or a command fails, say so and give the exact step. Do not recite this file to the owner.
0.7 Stay lean: this file loads every session, so read reference files only for the phase at hand, keep session notes in state files, and never paste the playbook into chat.
0.9 Fixes are recorded once, for every game (owner rule, 2026-10-13: "I do not want to go through all this for each and every game"). `fixesforgames.md` is the master list. (1) Start every new game from the starter kit (`shared/starter-kit/`, created with `tools/new_clone_from_kit.py <slug> <package> <game folder>`): it already contains the fixed speech, window, audio, healing, build, installer and measuring code. (2) Read section A of `fixesforgames.md` before S6.1 and the entries named for the phase before S7.1, S9.1, S10.1, S11.1. (3) At the end of every session, before `PROJECT_STATE.md`, add every bug, surprise or lesson of the session to `fixesforgames.md` as a new entry (template in section D) with its Check, and copy any improved file back into the starter kit. A lesson that exists only in a state file is a lost lesson. (4) After editing `CLAUDE.md`, a playbook or `fixesforgames.md`, run `python tools/sync_playbooks.py`: it copies all five files to every location (dev, games, kitchensinc, each game folder) and reports any copy that differs. (5) Tell the owner in one sentence which entries were added.
0.8 Automation first. Do everything you can yourself, in this order, before involving the owner: (1) read the game folder, spec, code, state files; (2) run a test, script, debugger, DOSBox-X, or tool; (3) search the web and official documentation (record sources in the spec); (4) install any free tool you need, user scope, no asking (section 1); (5) pick the sensible default, record it in `DECISIONS.md` with the test or later phase that would reveal it is wrong; (6) postpone to the later phase whose evidence will answer it (3.2.1). The owner is the last resort, and only for what nobody else can supply: what a sound sounds like or how the original plays when no tool can capture it; sign-in to accounts and other credentials; administrator rights, reboots, paid tools or accounts; hardware and platform choices (S12.1); permission claims from people connected to the original; optional-feature choices (JAWS support, 7.3.1); approval of public actions (8.3); scope exceptions (0.1). Never ask what you could look up, test, or default. An unanswered question is never a reason to stop: record it, continue with everything it does not block.
0.10 Clean uninstall, clean exit (owner rule, 2026-10-13, every game, program and utility, every platform). (1) Uninstalling deletes the program's own folder completely (Windows: the Inno script of 8.2; Linux, Android, macOS, iPhone: 9.1.1); the player's settings and own files live in the per-user folder, are kept by default, and the README says where they are. (2) Closing the program ends the process and releases every folder, file and background process: no service, autostart, helper or tray icon; the process never keeps its install folder as its working directory; it leaves through `finish()` with an exit deadline (7.2.1). (3) Every game has the scripted checks for both (8.2: `verify_installer.py`, `exe_smoke.py`, `who_holds_folder.py`) and they pass before an installer is called finished. Start from the starter kit, which has all of it.
0.11 Sound math: no numpy by default, numpy at the user's choice (owner decision 2026-10-13, every game, program and utility). Pitch, pan, volume, mixing, clipping and tone generation use `audioop-lts` (a 30 KB package) and plain Python, as the starter kit does: Brain went from 54 MB to 25 MB (64-bit) and 22.9 MB to 13.3 MB (installer) with the same sound (at most 2 of 32,768 apart). The user keeps the option of numpy for any new game, program or utility that needs it (heavy or real-time synthesis, filters, echo, FFT, many voices mixed at once; list in 7.1.1). Claude proposes numpy, with the reason and its cost (about 28 MB in a 64-bit build), in S6.1 or whenever such a need shows up, and the user decides; Claude never switches on its own and never in silence. The numpy code is ready in `shared/starter-kit/alternatives/numpy-audio/`: `python tools/new_clone_from_kit.py <slug> <package> <game folder> --numpy-audio` (7.1.1 says how to switch a game that already exists). Record the decision and its reason in the game's `DECISIONS.md`.
0.12 Customizable commentary and banter (owner rule, 2026-10-14, every game that has them: announcer remarks, jokes, taunts, cheers, random comments). The player can change the original lines, switch any off, and add new ones made of their own text, their own sound files, or both. The original lines are the defaults with permanent IDs, and with the file unchanged the game sounds exactly like the original. S4.5 lists every such pool as customizable, never "built in"; S7.7 builds it. Exception (0.27, 2026-10-22, sports games only): in a sports game's own mode (not its exact original mode) the default banter lines are radio-style banter, not the original author's jokes; amended 2026-10-26: in a sports game the original author's commentary is removed in every mode, the exact original mode too, and the radio crew's lines are the only commentary pools. Details: playbook 7.9; model: nfl4 `spec\CUSTOMIZABLE_CONTENT.md` section 12.
0.13 Features that belong to one game only (owner rule, 2026-10-14; today nfl4 only). The owner's seven extra in-game features of the NFL football game (timeouts, replay challenges, QB keepers, onside kicks, optional Madden-style playbooks, a Franchise mode, penalties with accept or decline; the NFL ones according to the NFL rules) are required for nfl4 and for no other game, program or utility. `games\kitchensinc\nfl4\spec\NFL_EXTRA_FEATURES.md` (decision D-040 there) is their authority and this file only points to it. Never copy any of it into the starter kit, `shared\`, `tools\`, a playbook or another game; `sync_playbooks.py` does not carry it. In nfl4: S7.3b to S7.7 build the hooks of that file's section 5 and keep the classic game exact (a recorded golden transcript); phase PX (SX.0 to SX.9) builds the features between P7 and P8; P9 waits for PX unless the owner says otherwise. Every NFL rule and Madden fact in it is tagged SRC-OFFICIAL, SRC-SECONDARY or UNVERIFIED and SX.0 settles them from the NFL rulebook and EA's own pages (0.3); Madden is inspiration only, with the trademark notice in README and About. Lessons from building them still go into `fixesforgames.md` (0.9), in general words.
0.14 Numbered sounds the player can extend, and optional commercials (owner rule, 2026-10-16, every game with sounds). Jim Kitchen's games name many sounds as a base plus a number (foot0.wav, foot1.wav, foot2.wav and so on) and the game draws one of them. In every game the player can add more files to such a family with no code change and no settings edit: a file named with a new number (foot15.wav) put in the sounds folder joins the family, the original files stay the defaults, and with nothing added the game is exactly the original. This is meant above all for comments and banter in sports games. Every game with natural breaks (halftime, end of a quarter, period or inning, between rounds, levels or games) also gets an optional commercial slot: the player puts own sound files in a `commercials` folder, a Sounds menu setting (off by default) plays one at a break, any key skips it, and the project ships none. Neither feature may change the game's logic, its random draws when nothing is added, the timing of results, or saved data. Only wavs that the code draws among for one event are a family: numbered names of different events (nfl4's foot14, foot10) are not. S4.1 and S4.5 find and list the families and the break points, S7.2 and S7.7 build them. Details: playbook 7.7.1; checklist item A60 and entry B-A19 in `fixesforgames.md`.
0.15 Detailed debug log in every game (owner rule, 2026-10-18, every game, program and utility; nfl4 now, released games such as Brain at their next release, one game per session). Players' computers differ from the owner's (Windows version and language, screen reader and its version, speech voices, sound devices, folders moved by OneDrive, antivirus) and Claude can neither see nor hear them, so a bug there can only be fixed from what the program wrote down. Every program therefore writes, from its first line, a detailed plain-text debug log in the per-user logs folder: a startup report of the whole setup (system, speech engines and voices, audio devices, folders, settings, customization files and their health), then every key, menu step, speech request and its result, sound played and the file chosen, file read, write and repair, setting change, slow step, caught error with its traceback, and the random seed, enough to replay a session. It is on by default, capped and rotated, never slows play and never stops the game when it cannot be written, holds no password, key, token, e-mail address or Windows account name, and never leaves the computer by itself. A menu command saves one problem-report file that the player sends to the owner. When a bug comes from another PC, Claude reads that file first (asks for it, never guesses), and every fix adds the log line that would have shown the bug. Details, full list, tests: playbook 7.11; checklist item A67 and entry B-R8 in `fixesforgames.md`.
0.16 The spoken welcome that names every game (owner rule, 2026-10-18, every game, program and utility; nfl4 now, released games at their next release). The game name is said as a person says it, with the letters of an acronym spaced so the voices spell them ("N. F. L."). The welcome replaces the spoken startup title of 0.5.1 and carries the 0.5 attribution for the startup speech; the window title stays as 0.5.1; About, help and README keep the longer "inspired by" text and, for Jim Kitchen games, the respectful note. Details, per-kind wording, tests: playbook 7.12; checklist item A67 and entry B-S26 in `fixesforgames.md`.
0.17 Key help (owner rule, 2026-10-20, every game, program and utility). A session that adds a key adds it to the list in the same session; a test requires it. Details: playbook 7.13; checklist item A73; entries B-W13 and B-W14 in `fixesforgames.md`.
0.18 The game's author in every sentence that names the maker (owner rule, 2026-10-20, every game, program and utility; nfl4 now, released games at their next release). L. football version 4 By Jim Kitchen", "This is week 3 of Jim's N. F. 0.19 Real names, no typing (owner rule, 2026-10-20, every sports game and every similar game that has teams, coaches, players, drivers, athletes or other real people; nfl4 first). The player never has to type a coach's or a player's name. Claude researches the real names itself (the league's, teams' or federation's official pages first, then reliable secondary sources; sources, date and terms recorded in the spec), builds them into the game as customizable files with a refresh path (a new season is a file update, not a code change), and offers the real name as the default wherever the original made the player type one (a coach's name, a roster). Typing another name stays possible for a player who wants it and is never required. The data is facts only (names, teams, positions, numbers): no logos, no photographs, no ratings copied from commercial games; the README says the names are used descriptively; Claude is not a lawyer. nfl4: the real head coaches and rosters of the 32 teams (NX-N, session SX.11, `spec\NFL_EXTRA_FEATURES.md` section 18). Details: playbook 7.14; item A74; entry B-P120.
0.20 The real sport's full set of plays (owner rule, 2026-10-20, every sports game; nfl4 first). Where the original has a short list of plays or options (Jim Kitchen's NFL football has a small set of offensive and defensive calls), the game keeps those exactly in the original's mode and, in the mode with the real rules, offers ALL the plays and options of the real sport, never only the original's: researched from official and reliable sources, tagged like every rule (SRC-OFFICIAL, SRC-SECONDARY, UNVERIFIED), each with its outcome model decided and tested, grouped so a blind player reaches them quickly. nfl4: every real NFL offensive, defensive and special-teams play type and formation (NX-P, session SX.10, `spec\NFL_EXTRA_FEATURES.md` section 18). AMENDED 2026-10-20 (b), the owner's second statement while playing nfl4: "I need all real and Madden NFL plays in my version of the game. This game is no longer a clone of Jim Kitchen's games, it is loosely inspired by him. I just want it to have a play style that is similar to how Jim Kitchen's game behave for the user." So for nfl4 (and a sports game the owner names the same way): the game's identity is "loosely inspired by" the original, not a copy; its DEFAULT mode offers every real NFL play and every play of Madden NFL's playbooks (plays are football concepts; Madden's names, art, ratings and text are not copied, 0.13 and the trademark notice stay); what stays the original's is how the game behaves for the player: short spoken menus read by number or letter, the same function keys (F1 repeat, F2 replay, F3 score, F4 clock, F5 to F7 help), the same pace and sounds, nothing a sighted screen would need. The exact original (Classic) stays as a switch, never the default. AMENDED 2026-10-20 (c), the owner's instruction: "all madden nfl and real nfl plays must be implemented into this game, and into other football and sports games that I create from scratch or games that I base loosely on Jim Kitchen's games." So this is a standing rule for EVERY football game and EVERY other sports game of the owner's, whether it is made from scratch or based loosely on one of Jim Kitchen's games (or a PCS Games title): every real play of the sport and every play of the best-known commercial game of that sport (football: all real NFL plays and all Madden NFL plays, as football concepts; other sports: the real sport's full set of plays, moves and options and those of the leading commercial game's playbooks, as concepts) is implemented in the game's default mode, never a subset; the spec's requirements list this at S4.5 (or at the start of a from-scratch game) and a game is not finished while any real or commercial-playbook play is missing or untested. Names, art, ratings and text of the commercial game are never copied (0.13's trademark notice stays). Details: playbook 7.14; item A74; entry B-P119.
0.21 No looping sound outlasts its event (owner rule, 2026-10-20, every game, program and utility). A sound that loops while the program works (the original's intro, crowd beds, any ambient bed) has one named event that ends it, never plays on while the program waits for the player to answer or choose (a menu, a name, a team, the kind of season), has a safety stop at the first such wait, and logs when it starts and when it stops. nfl4's intro (foot0) ends when the welcome sentence ends, in every start-up path. A test starts the program in every start-up path (first start, later start, new season, saved game, a franchise) and requires that no loop is playing at the first prompt.
