## How this file works (the agent: follow it every session)
1. Before S6.1, S7.1, S9.1, S10.1 and S11.1 of a game, read section A (the checklist) and the entries of section B that name your phase. Do not rediscover a fix that is written here.
2. Start every new game from the starter kit (section C). It already contains the fixed code and the measuring tools.
3. At the end of every session, add every bug, surprise or lesson of that session as a new entry (template in section D), in this file, before writing `PROJECT_STATE.md`. Do not leave a lesson only in a state file. Keep each entry short, with a Check (a test or tool that proves it). If an entry changes the starter kit, change the kit too.
4. Longer explanations live in the playbooks (section numbers are given); this file is the quick index of what went wrong, why, how it was fixed and how to check it.
5. After editing this file, copy it to every location listed in `AGENTS.md` 0.9 (script: `tools\sync_playbooks.py`).

## A. New-game checklist (do these from day one; each item is a fix that cost time on Brain)
Spec and analysis (P1-P5)
- A1. Search for DirectX for VB class and interface IDs as well as names; check that every COM class the original needs is registered on this PC before planning to run the original (B-P1, B-P2).
- A2. VB6 native code: the statement table decides where `Resume Next` continues after an error inside an `If` condition. Check it (B-P3).
- A3. The original is not run unless a tool is free of side effects: desk work plus listening to the game is enough (B-P4).
Language and speech (P6, P7)
- A4. Python 3.14, pygame-ce, audioop-lts (no numpy unless the user chooses it, rule 0.11, B-A6), pywin32; NO GUI toolkit: the window is the ctypes Win32 module of the starter kit (B-W1). Install both bitnesses at once (B-B8).
- A5. SAPI 5: render each text in memory, cut the silence at both ends, play through waveOut; per-voice speed probe; voice list from SAPI's own enumeration (B-S1 to B-S6, B-S9).
- A6. NVDA: blocking `speakSsml` on a worker thread, cancel only while speaking, retry a call cancelled by nobody (B-S10 to B-S12). Never the SSML mark callback.
- A7. JAWS: COM `FreedomSci.JawsApi`, stop is `SayString(" ", True)` (never `StopSpeech`), wait by the measured estimate (B-S13 to B-S15).
- A8. Crash guard for the saved voice from the first session (B-S17). Every engine call guarded in the manager (B-X2).
- A9. Every blocking prompt that precedes a sound or action gets the "start right away" setting (default: the original's wait) (B-S16). The default is the original's wait; the player may switch it (owner decision, B-S16).
- A10. Keep the arrow-key labels short; hints go in F1 (B-S7). Key echo, typed-ahead and held keys follow the spec (B-W2).
Sound (P7)
- A11. Player files are plain-line text with healing, never strict JSON (B-A1). Resolution chain and self-healing from the kit.
- A12. Mixer tests use SDL's dummy driver for logic, SDL's disk driver to read the mixed samples back (B-A14) and the real device at volume 0 for timing (B-A2, B-X19). The default code uses no numpy and no `pygame.sndarray`; in the numpy variant do not exclude `pygame.sndarray` (B-A3).
Tests (P7, P8)
- A13. Build the virtual-clock rig with scripted keys in the first logic session (B-X1). Stress tests must fail on any logged error (B-X2). Fake engines behave like the measured real ones (B-X3).
- A14. Run every real-thread test 30 times per bitness before trusting it (B-X5). Run a new test file with a timeout first (B-X7).
Build and installer (P9, P10)
- A15. Build outside OneDrive, absolute `--add-data` paths, slimming recipe, prune leftover DLLs, clear the Control Flow Guard flag, smoke test each speech mode in both bitnesses (B-B1 to B-B8).
- A16. Test the BUILT exe with every exotic voice installed on the owner's PC (`exe_voice_check.py`) (B-S17, B-X4).
- A17. Installer: `{param:}` does not work in the uninstaller, the uninstaller finishes asynchronously, per-user default, never touch AppData; run the scripted installer verification before any owner session (B-I1 to B-I5).
GitHub and release (P11)
- A18. Public history is a separate clean chain from a temporary index; scrub the original author's contact details; MIT text plain plus a notice file; `.gitignore` for original-derived files and the playbook copies (B-R1 to B-R5).
Measuring (any phase)
- A19. When the owner reports "slow", "laggy", "silent pause": measure at the speakers by loopback before changing code (B-T7). Every claim of a documented API is checked by a test on the real engine (B-S13).

- A21. Keep the playbook copies in sync with the sync script after every edit (B-T5).
