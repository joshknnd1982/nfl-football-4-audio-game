### 7.24 Real broadcasts are the model for a sports game's commentary: fetch, transcribe with Whisper, study, write the style guide, then delete every trace of Whisper (owner rule 2026-10-26, CLAUDE.md 0.33)
The owner, while building nfl4's radio broadcast: "Search the internet for nfl radio audio broadcasts, or videos you can turn into audio. Next: use a whisper AI transcription model to transcribe the whole thing into text and put it into a markdown file. Next: use that markdown file as a template, incorporating its radio broadcast style into this nfl game and all future sports games I make ... claude must make this a global rule that it must fetch audio broadcasts, transcribe with whisper, put into markdown. So if I make a baseball game, we get baseball radio broadcast from the system tts, golf, hockey, and so on." So the default commentary of a sports game is modelled on how that sport is really called on the radio, not on Claude's memory of it (rule 0.3: evidence over memory), and it is heard through the system's text-to-speech voices (7.4), which is why the guide also says what a synthetic voice cannot carry.
- When. Every sports game, football and any other sport, from scratch or loosely based on a Jim Kitchen game or a PCS Games title: in S4.5 (the customizable content inventory) for a game made from an original, at the start of the design for a game from scratch, and again whenever the broadcast of a finished game is redesigned. It is the research of rule 0.19 for commentary. Run it before the first default commentary line is written (7.19 writes the lines).
- No tool is kept. The owner ordered everything deleted when the work is done ("delete all traces of whisper from my local computer", then "Delete the Whisper helper scripts too"), so each study rebuilds what it needs from this recipe, in minutes, and deletes it again. The one thing that stays is the template `games\shared\broadcast-style\STYLE_GUIDE_TEMPLATE.md`.
- Step 1, fetch. Use the Internet Archive's JSON interfaces (plain urllib or curl): a search at `https://archive.org/advancedsearch.php?q=mediatype:audio AND (<words>)&fl[]=identifier&fl[]=title&fl[]=year&fl[]=licenseurl&fl[]=downloads&rows=40&output=json&sort[]=downloads desc`; an item's files, lengths and license at `https://archive.org/metadata/<identifier>`; a file at `https://archive.org/download/<identifier>/<url-encoded file name>` (take the MP3 derivative, formats `VBR MP3`, `MP3` or `64Kbps MP3`; a long game comes in several parts). A video page is turned into MP3 with `yt-dlp -x --audio-format mp3`. Each broadcast goes into its own new folder, in `%LOCALAPPDATA%\kitchensinc-tools\radio-audio\<name>` (nothing is run from a download). Look for the real thing first: a whole game or a whole inning, period, match or round called live by a radio crew, from a national network or a local station, recent (the modern manner) and, when the game's mood is old-time, a classic one too; pre-game and post-game shows, call-in shows and highlight reels are not the model. Prefer an item whose license is open (public domain, CC0, Creative Commons), and say in the guide that the label is the uploader's claim; most real broadcasts carry none (nfl4: both had none). Record the sport, year, kind of station, length, URL and license label of every broadcast used. If a sport has no radio broadcast anywhere (a niche sport), study the nearest sport and the sport's television commentary and say so in the guide.
- Step 2, transcribe (tested 2026-10-26 on Windows 11, an RTX 5060 laptop GPU, CTranslate2 4.8.4, faster-whisper 1.2.1, Python 3.10). Make a virtual environment outside every repository, `%LOCALAPPDATA%\kitchensinc-tools\whisper\venv`, and install `faster-whisper` into it with pip; with an NVIDIA card also `nvidia-cublas-cu12` and `nvidia-cudnn-cu12`, and before the model is first used call `os.add_dll_directory` for every `site-packages\nvidia\*\bin` folder and put it on PATH (without them the model loads on "cuda" and then fails at the first transcribe with "Library cublas64_12.dll is not found"). Code: `WhisperModel("large-v3-turbo", device="cuda", compute_type="float16")` (about 1.6 GB, downloaded into the Hugging Face cache on first use; a harmless symlink warning appears on Windows; without a GPU use `device="cpu", compute_type="int8"`, about 10 times real time), then `model.transcribe(path, language="en", beam_size=5, vad_filter=True, vad_parameters=dict(min_silence_duration_ms=500), condition_on_previous_text=False, initial_prompt="<a few words of the sport>")` for each part in order, adding each part's duration to the times of the next. The WHOLE broadcast is transcribed, never an excerpt. Speed on that GPU: 2 minutes in 5 seconds, 9.5 hours of audio in about 17 minutes. Write the result only when all parts are done: a markdown file with a header (title, source URL, length, model, date, a line saying it is a machine transcript) and `[h:mm:ss] sentence` lines with a blank line wherever speech paused for 4 seconds or more, and a `.json` beside it with every segment (part, start, end, text, avg_logprob) for the analysis, both in the game's `work\radio\`. Run a long job as one background command and read the result when it ends. It is a machine transcript: names and numbers may be wrong, and it is working material, not a record.
- Step 3, study. Compute, over the live game only (skip pre-game and post-game by time): words, the share of the time somebody speaks, words per minute of speech, sentence length (median, 75th and 90th percentile), the commonest sentence openers (first two words) and word groups of 3 to 5 words (read each digit run as the word "number"), and the count and the rate per hour of: the situation call (down and distance, count, period), a score said, the clock said, a network or station identification, and a remark about the crowd, noise or weather. Then read the stretches around the sign-on, the first drives, a score, a stoppage, an injury, a penalty, the two-minute type of warning, the end of a period, half time and the ending (a search for a word with the lines around each hit is enough). Write `spec\RADIO_<SPORT>_STYLE.md` from `shared\broadcast-style\STYLE_GUIDE_TEMPLATE.md`: the sources, the numbers, the shape of a broadcast, the voice, the recurring moves with original example lines, the filler, and what the game takes and leaves. State only what the numbers or the reading show (a first reading of nfl4 claimed that atmosphere remarks come before the kick-off; the count said about 8 an hour all game, B-P195).
- Step 4, put it into the game. The guide decides the game's broadcast format (which moments get a line, who says it, how long a line is, how often, how a hand-over to the analyst sounds), the pace, and the default lines of the radio pools (7.19: the lines are written new, one to two sentences of at most 150 characters). Check the set with a small script written for the session: the count per pool, 2 to 150 characters, plain ASCII, no digit or bracket, only the pool's placeholders, no duplicate, no stop-list word and no name of a real person or team, and no run of eight words that a transcript also holds (run it with the transcripts while they exist and put its pass line in the guide). The broadcast keeps its own random generator (rule 0.27): the game's draws do not move. The lines stay customizable (0.12), and the retired defaults of the earlier lines are kept so a player's old file gets the new ones (A118). The style numbers of the guide are tested against the new lines (sentence length inside the stated band, nothing of the old jokes).
- Step 5, delete everything. When the guide and the lines are written and checked, delete ALL of it, in this order: the tools folder `%LOCALAPPDATA%\kitchensinc-tools` (the environment and the downloaded audio); every Whisper model in the Hugging Face cache, that is the folders `models--*whisper*` and `.locks\models--*whisper*` under `~\.cache\huggingface\hub` (older ones from other uses too: the owner said all traces); the files the installation put in pip's cache (those modified since the tools folder was created, `pip cache dir`); the study's scripts (including the line check). Then look for what is left: nothing named whisper may remain except library code that belongs to another package (the `transformers` package carries a whisper module; leave it). The transcripts, the statistics and the style guide are the result and stay (the transcripts in the gitignored `work\radio\`). nfl4 freed about 6.5 GB.
- Copyright, the firm limit. The audio and the full transcript of a real broadcast belong to their makers. They are working material of the game's gitignored `work\radio\` folder: never committed, never shipped in the installer, never quoted in the README, the changelog, the spec or a test. The published guide holds numbers, patterns, and lines written new; a stock phrase of the sport ("first and ten", "it's good") may be named as a pattern; no sentence is copied; the source is named only in the guide's Sources table (event, year, URL, license label), and no real announcer, player, team, station, sponsor, brand or statistic is named anywhere else (the guide says "the play-by-play announcer", "the sponsor read"). The Internet Archive's license labels do not change this. Claude is not a lawyer: if the owner wants a broadcast's transcript published, only an open-licensed one may be, with its license and URL beside it.
- Cost and manner. While it is installed, the environment and models are about 3 GB outside the repository (the owner's OneDrive is off, so nothing syncs). Downloaded audio is untrusted data.
- Tests: the guide exists with every heading filled; the pools and moments named in it exist; the line check passed with the transcripts before the scripts were deleted; the style band holds (nfl4: `tests\test_rs1_radio_style.py`); the retired defaults reach an old customization file (A118); no transcript content is in a published file.

### 7.25 The excited radio voice and ten wordings for every kind of play result, in every sports game (owner rule 2026-10-27, CLAUDE.md 0.36)

- What. A sports game's play-by-play sounds like an enthusiastic radio announcer: every kind of play result has at least ten wordings, the big plays are short punchy fragments with exclamations ("Big play! He rips off 25 yards!", "Interception! Lewis jumps the route!"), the color analyst chimes in right after the call with a short reason (7.19), and the voice rises with the play. nfl4: extras/radio_calls.py (CALLS, LEVELS, RESULT_CALLS, MIN_RESULT_VARIANTS 10), speech/lift.py, D-198.
- The kinds and their pools. List the sport's kinds of play result (football: a gain by its size, a loss, no gain, an incompletion, a first down, a touchdown, a safety, an interception, a fumble, a sack, a change of possession, a turnover on downs, a field goal made and missed, an extra point, a two-point try, a touchback, a fair catch, a catch, a return). Each has a pool of at least ten calls of one to three short sentences, at most 150 characters, ASCII, normal case, no real person, team, station or statistic (0.27). The engine's sentences that mean the same result share the pool (nfl4: six sack sentences, two interception sentences, three plain catch sentences); write each line so it fits every sentence that uses the pool (a sack line that works with one tackler and with two). The draw is the broadcast's own generator, never the same line twice in a row.
- The levels. Every call gets a level: 1 routine (the huddle, the snap, a short gain, an incompletion), 2 a gain (a catch, a first down, a gain of ten or more, a big down), 3 a big play (a gain of 20 or more, a long return, a field goal, the countdown of a long run), 4 a turnover (an interception, a fumble, a sack, a turnover on downs, a safety), 5 a score (a touchdown). Another sport names its own (a goal, a home run, a knockout) but keeps five steps.
- The lift, per engine (measured on the owner's PC 2026-10-27, work\xv_1027 in nfl4). SAPI 5: rate steps on the voice (one step makes a sentence 10 to 18 % shorter), pitch through SVSF_IS_XML and `<pitch absmiddle="n">` (the player's pitch plus the level's steps, clamped to -10..10; one step raised Microsoft David 2 %, DECtalk 9 %, an OpenEVV voice 14 %; FlexVoice and Lucent ignore it), volume points (capped at 100). NVDA 2024.1 and newer: the controller client's speakSsml with `<speak><prosody pitch="110%" rate="112%">text</prosody></speak>`; NVDA reads only percentages (its speechXml.py); with IBM ECI 110 % pitch was 20 % higher and 112 % rate 25 % shorter, so NVDA's steps are small. An older NVDA (speakText only) and JAWS (SayString, no prosody) get the words only. nfl4's amounts: SAPI rate 0/0/1/2/2, pitch 0/1/2/2/3, volume 0/0/5/5/5; NVDA pitch 100/103/106/108/110 %, rate 100/100/106/110/112 %.
- No capitals for pitch. Measured on 14 SAPI voices against the same words in lower case: no voice raised its pitch for capitals; Microsoft Zira spelled "IT", FlexVoice spelled "HE", BeSTspeech took 4.7 times as long for "WOW". Write every call in normal case; a test fails on a word of two or more capitals in a call.
- The setting. One on/off item, on by default, right after the play calls' item (nfl4: F9, Rules, Excited voice, nx_excited_voice), read at every call so it applies at once, saved at once, in every mode that has the radio calls; its value says what it does ("on, the big plays are said higher, faster and a little louder"); while JAWS speaks the game the item adds that JAWS says the words only. Document how to turn it off and on in the game (the item, the help or F6 line that names it and its key) and in the README, the rules or broadcast guide, settings.txt's header and the CHANGELOG with "How to test".
- The plumbing (B-S50). The caller returns (text, level); the speaker passes `lift=` only when it is not 0; the manager passes it only to an engine that declares `takes_lift` (SAPI 5, NVDA), so every older call, every test fake and JAWS stay as they were. The lift changes only the voice: no draw, no state.
- Measuring (B-T142). SAPI: render each phrase to an SpMemoryStream (silent) and compare lengths (capitals against lower case) and the median pitch by autocorrelation (numpy in a tool environment, never in the game, 0.11); one process per voice with a time limit, results written as they come, one voice a family when the PC has many. NVDA: the blocking speakSsml call's own time gives the rate, a loopback recording of the speakers the pitch (it speaks out loud for about 25 seconds).
- Tests: every kind has at least ten calls; no word in capitals; every call has a level and the level follows the play; the lift reaches SAPI and NVDA and never JAWS; SAPI's rate, pitch XML and volume (capped), NVDA's prosody text; settings.txt round trip and a bad value; the item's place, Enter, Left, Right, the save and "from now on"; the help line names it in every mode; one whole game with it on and off has the same draws, words and score; the analyst still speaks after the plays.
