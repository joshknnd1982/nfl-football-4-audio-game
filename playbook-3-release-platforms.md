## 8. Windows build, installer, GitHub (P9-11)

### 8.1 Compile (P9)
Build standalone Windows executables with all dependencies bundled (PyInstaller usual for Python, Nuitka alternative; verify). 32-bit build needs a 32-bit toolchain, 64-bit a 64-bit one; check what is installed and install what is missing yourself (user scope; ask only if it needs administrator rights). Bundle the right NVDA DLL per build (JAWS support bundles nothing: it calls the player's installed JAWS, 7.3.1), audio libraries (no GUI toolkit: the window is ctypes, 7.1), attribution text. Do not bundle original wavs or EXEs unless section 10 allows; if the game needs original sounds, first run asks the player (accessibly, with spoken instructions) to point to their own copy of the original game folder. Run builds from another folder with the source hidden to catch missing files; record tool versions and SHA-256 of outputs in `release/`. Smoke test (S9.2): each build starts, speaks the 0.16 welcome (7.12), plays a sound, exits cleanly, and leaves a debug log with the whole startup report and the last line `closed` (7.11); 32-bit loads the 32-bit DLL, 64-bit the 64-bit one; with JAWS support enabled, a machine without JAWS still starts and speaks through SAPI5 with no crash; fix problems before the installer.

Size budget and slimming recipe for Python builds (Brain P10: 92 MB to 54 MB for 64-bit, 63 MB to 31 MB for 32-bit, installer 44 MB to 23 MB; Brain 1.0.3 without numpy: 25 MB, 21 MB, installer 13.3 MB). Measure first: list the biggest folders and DLLs of `dist/<name>/_internal`. In order of payoff:
1. No GUI toolkit when the game has no controls (wxPython was 22 MB): a ctypes Win32 window (7.1).
2. Exclude what the game never imports: `--exclude-module ssl --exclude-module _ssl --exclude-module _hashlib` (drops OpenSSL, 7 MB; hashlib and random fall back to built-in code), `tkinter`, `pytest`, and the pygame modules a mixer-only game does not use (`pygame.font`, `freetype`, `image`, `imageext`, `transform`, `draw`, `mask`, `pixelarray`, `pixelcopy`, `scrap`, `_sdl2`, `surfarray`, `camera`, `gfxdraw`). Add `--exclude-module numpy` (the default sound code of the starter kit needs none, 7.1.1) and check that `_internal` holds no numpy folder and no OpenBLAS file. Only for a game whose user chose the numpy variant (rule 0.11): do NOT exclude numpy, and do NOT exclude `pygame.sndarray` if the sound output builds sounds from arrays (Brain 1.0.2's did: the first slim build played nothing; the smoke test caught it).
3. PyInstaller's pygame hook copies every DLL of the package whatever was excluded: delete the leftovers after the build in the build script (SDL2_image, SDL2_ttf, freetype, libjpeg, libpng, libtiff, libwebp, libwebpdemux, portmidi, libssl, libcrypto), from `_internal` and `_internal/pygame`. Keep the SDL_mixer codec DLLs (ogg, opus, wavpack, xmp) when players may use ogg, flac or mp3 sounds.
4. What stays: Python 10 MB, SDL and mixer 3 MB, pywin32 3 MB, the game itself (Brain 1.0.3: 64-bit folder 25 MB, 32-bit 21 MB). numpy with its OpenBLAS adds about 28 MB to a 64-bit build and about 10 MB to a 32-bit one, only when the user chooses it (7.1.1).
5. Prove nothing is missing: the exe smoke test in every speech mode (sapi, jaws with JAWS absent, and so on), both bitnesses, plus the installer verification script; keep the exclusion list in the build script with a comment per group, and write the final sizes and file counts in `release/BUILD_INFO.md`. 6. Clear the Control Flow Guard flag of the PyInstaller exe after the build (`clear_cfg_flag.py`, playbook 7.4.5): without it the 64-bit exe dies with 0xC0000409 as soon as a voice that emulates a CPU (SmoothTalker) runs, while the same voice works from python.exe. The smoke test checks the flag and `exe_voice_check.py` starts the exe with such a voice.
Backslashes in build scripts written through the shell tool get mangled (`\b` becomes a backspace): write build scripts with the file tool.
Build in a folder outside OneDrive; the installer compresses both builds into one setup (about 40 percent of the folders' size).

### 8.2 Installer with Inno Setup (P10)
Use the owner's Inno Setup 6 (section 1): one setup file, standard wizard controls that work with screen readers, 32/64-bit support, Start menu entries, optional desktop shortcut, uninstaller. WiX or NSIS only if the owner asks or Inno cannot do something needed.

Never overwrite or delete the player's custom sounds (7.7) or customized names and data (7.9) in the per-user data folder on update or uninstall (a plain uninstall keeps that folder; the program folder itself is removed completely, see the uninstall bullet below). Also build a portable zip. Names: `<slug>-setup-1.0.0.exe`, `<slug>-portable-1.0.0.zip`.
- S10.2: compile with `"C:\Users\joshk\AppData\Local\Programs\Inno Setup 6\ISCC.exe" "<full path to release\installer.iss>"`, passing version and build folders as defines (e.g. `/DAppVersion=1.0.0`). On failure read the error, fix, rerun; not built until the setup file exists in `release/` with a sensible size. Compiler not at that path: search usual Program Files locations and the registry uninstall keys; if it is truly missing install it yourself (winget package `JRSoftware.InnoSetup` or the official installer, per-user if it allows) and record the path in section 1 of `PROJECT_STATE.md`. Unsigned installers may trigger SmartScreen: put that and how to proceed in the README and tell the owner once; code signing is optional and paid, so only mention it.
- Inno Setup lessons from Brain (P10, 2026-10-13): `{param:NAME}` is NOT expanded inside the uninstaller, so a switch such as `/DELETEUSERDATA=1` must be read by hand with `ParamCount` and `ParamStr` (a first version using `{param:}` silently ignored the switch; only the scripted test caught it). Ask about the player's settings in `CurUninstallStep = usPostUninstall` with a default of No, and let a silent uninstall keep them unless the switch is given, so both outcomes can be tested. Update over an older version: same AppId, `[InstallDelete]` of the program's own library folder (stale files), never anything the player may have put in the sounds folder. Compile an older-version installer for the update test with `/DAppVersion=0.9.0 /O<scratch>`.
- Uninstall removes the WHOLE program folder, and closing the program lets go of it (owner bugs on Brain, 2026-10-13: "the My Brain folder is left under Program Files" and "folder in use until I restart"; fixesforgames.md B-U1, B-U2, B-U3). Every Inno script of a game has: `[UninstallDelete] Type: filesandordirs; Name: "{app}"` (Inno removes only what it installed, so one file the program or the player made in the folder keeps the folder for ever); `uninsrestartdelete` on the `[Files]` entries (last resort for a file still in use: removed at the next restart); `WorkingDir: "{userdocs}"` on every `[Icons]` entry and on the `[Run]` "start now" entry, which also gets `runasoriginaluser` (a process whose current directory is the program folder locks it with nothing showing in Task Manager, and the old `WorkingDir: "{app}"` started the game exactly that way); in `[Code]`, at `usUninstall` a `StopRunningCopies` that ends every process whose program file is inside `{app}` (PowerShell `Get-Process | Where-Object { $_.Path -and $_.ProcessName -notlike 'unins*' -and $_.Path.StartsWith('<app>\', OrdinalIgnoreCase) } | Stop-Process -Force`, hidden, waited for, run through `{sysnative}\WindowsPowerShell\v1.0\powershell.exe` when `IsWin64` because the 32-bit uninstaller stack cannot read the path of a 64-bit process; never touch `unins*`: killing the waiting first-phase uninstaller made the uninstaller return exit code -1) followed by a short sleep, and at `usPostUninstall` a `RemoveFolderWithRetries` that repeats `DelTree(folder, True, True, True)` up to 20 times at 0.5 s intervals, for `{app}` and also for the settings folder when the player chose to delete it (a virus scanner or Explorer can hold a file for a moment; one verification run once left the settings folder behind without the retries). The player's own sounds and settings belong in the per-user data folder, which a plain uninstall keeps; say in the README and the installer info page that anything put into the program folder is removed. Reproduced here: an uninstall while the game is running left the folder behind and the game kept running (uninstaller exit code 0); the owner's all-users case needs elevation and was not reproduced, so the fix is defense in depth (installer side here, program side in 7.2.1). Manual installer tests: see fixesforgames.md B-T11 (Git Bash rewrites `/SWITCH` arguments; an ad-hoc uninstall touches the REAL per-user folder).
- S10.3 verification, scripted first. Write it once as `game/tools/verify_installer.py` (Brain has the model: install an older version silently with `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CURRENTUSER /DIR=<scratch outside AppData\Local>`, plant a stale library file and a player sound, install the new version over it, check the registry version, stale file gone, player file kept, 64-bit build chosen, Start menu entries, start the installed exe with an empty data folder and check the files it recreates and its debug log (the startup report complete and the last line `closed`, 7.11; `--problem-report` makes its zip with the listed members), silent uninstall removes the whole program folder, the Start menu folder and the registry entry and keeps settings, the exe started with its own program folder as working directory and closed politely ends within 10 s and the folder can then be renamed and no process holds any of its files (`game/tools/who_holds_folder.py`, Windows Restart Manager), an uninstall while the game is running ends the game and leaves no folder, uninstall with the delete switch removes the settings and the logs (without the switch both stay, 0.10, 7.11); 31 checks on Brain 1.0.2). The delete test touches the REAL per-user folder, so copy it away first and put it back in a `finally`, and diff it afterwards. The uninstaller finishes in a temporary copy of itself after its own process has returned, so the script must poll (up to 20 s) for the registry entry and the folders to disappear instead of sleeping a fixed time (a fixed 2 s sleep made the delete check fail one run in two). Run everything that can be automated and record each result: silent install into a temporary folder or Windows Sandbox (availability checked in S0.1; enabling it needs administrator rights and a reboot, so ask only then, else use a temporary folder and say what was not isolated), silent uninstall, install over an older version, file and settings checks, deleting customization and sound settings files to confirm they are recreated with original values (7.10), launch and speech-backend checks with fake and real backends where possible. Then one owner session, keyboard-only, with a short checklist read aloud: (1) installer runs keyboard-only and the screen reader reads every page and button; (2) game starts, speaks attribution, menu speaks; (3) speech works with NVDA and via SAPI5 without it (and with JAWS, if JAWS support is enabled and the owner has JAWS, 7.3.1); (4) SAPI5 list appears and is stable; (5) sound plays, volume works; (6) settings persist; (7) first-run flow for original sounds works if needed; (8) uninstaller removes the program, keeps saves and settings or asks; (9) installing over an older version keeps settings; (10) deleting customization and sound settings files recreates them with original values and the game runs normally (7.10); (11) the first words spoken are the welcome of 0.16, and the "Save a problem report" item says where it saved the zip (7.11, 7.12). Items already proven by the scripted run are not repeated for the owner unless they need ears. Owner has the final say.

## 9. Optional platform phases (P12-17)

### 9.1 Rules
Optional: the Windows release is complete without them; never start one unless asked. They can run later in any future session, needing only the frozen spec, tagged Windows game, `PROJECT_STATE.md` (read them first, say what changed). One game, one platform per phase. At the start of a platform phase audit the tools that platform needs and install what can be installed without administrator rights or payment (JDK, Android command-line SDK, WSL, and so on); ask only about hardware, accounts, signing credentials. Every port meets the Windows requirements: faithful to the spec, attribution, game volume and speech rate/pitch/volume controls, accessible, sound replacement (7.7), name customization (7.9), self-healing files (7.10), stable voice list with hundreds or thousands of entries (7.4 rules), uninstall that removes the program's folder and a process that really ends when closed (9.1.1), the detailed debug log and the problem report in the platform's own places (7.11), and the spoken welcome (7.12). Every port uses the platform's own system voices so the player can pick any voice, through one speech interface with one backend per platform. Never claim a build works where it was not run: label builds tested (where) or built but untested. Public actions follow the single-approval rule (8.3). Keep keys, keystores, certificates, passwords out of the repo and chat; tell the owner where they are and to back them up.

### 9.1.1 Uninstall and process lifetime on every platform (owner rule 2026-10-13, from the Brain bugs B-U1 to B-U3)
The owner's rule: uninstalling must delete the program's own folder on every platform, and closing the program must end it completely and release every folder, file and background process. Nothing of the program runs when it is closed: no service, daemon, launch agent, login item, scheduled task, helper process, tray icon or autostart entry (a game or utility that wants one needs the owner's explicit yes). Closing the main window or leaving through the menu ends the process within 2 s of the last thing it says; the process never keeps its install folder as its working directory; the program writes nothing into its install folder at run time (settings, saves, caches, logs, bytecode caches go to the per-user data folder; if a runtime must write there, the uninstall script removes it). Per platform, written from the platform's rules and NOT yet tested here (no build yet): the first port that is built tests its row and records the result in `fixesforgames.md`.
- Linux .deb or .rpm: the package manager removes the files it installed, but anything made at run time inside the install folder (Python `__pycache__`, logs) stays and keeps the folder, so install under `/opt/<slug>` or `/usr/lib/<slug>`, byte-compile in `postinst`, set `PYTHONDONTWRITEBYTECODE=1` in the launcher, and make `postrm` (remove and purge) `rm -rf` the install folder and `rmdir` the empty parents. Per-user data (`~/.config`, `~/.local/share` under XDG) is outside what a package script may touch: document the path in the README and ship a documented "remove my data" command. AppImage: nothing is installed, deleting the file is the uninstall, per-user data as above; the AppImage mount point must not stay mounted after exit (check `mount | grep <slug>` after closing). Flatpak: `flatpak uninstall --delete-data <id>` removes program and data; document it. tar.gz: documented as delete the folder.
- Android: uninstall removes the app and its app-private data by itself; files the app wrote to shared storage (for example an exported sounds folder in Documents) stay, so write there only when the player asks and say where in the README. No foreground service, boot receiver or alarm that outlives the screen; on exit release the audio focus, the sound pool and the TTS engine (`TextToSpeech.shutdown()`), then `finishAndRemoveTask()` (a lingering task is the Android form of a hidden process). Check after exit: `adb shell ps -A | grep <package>` shows nothing within a few seconds.
- macOS: an app bundle is removed by dragging it to the Trash, which leaves `~/Library/Application Support/<vendor>/<game>` and preferences: say so in the README and put an `Uninstall <game>.command` script (removes the bundle after confirmation and, only if the player answers yes, the data) in the disk image; never install launch agents, login items or system extensions; Cmd+Q and the menu exit end the process (`NSApplication.terminate`, no background app left; check `pgrep -f <game>` after exit).
- iPhone: deleting the app removes its sandbox; no background modes (audio background mode only if the owner asks), so the app is suspended and released when closed; no data outside the sandbox.
- Windows: B-U1 and B-U2 (8.2 above, 7.2.1).
